# Day 8: Course Reflection

The most difficult concept in this course was understanding how to design systems that remain correct when many users make requests at the same time. Concepts such as database transactions, concurrency, caching, and error handling required me to think beyond writing code that works for one user. I overcame this challenge by completing the daily assignments, studying examples, revising work based on assessment feedback, and practising how to explain my technical decisions. I learned that reliable software must protect data consistency while remaining responsive under heavy traffic.

Based on the feedback I received on my QuickNotes capstone, I would improve the documentation, validation, and error handling. I would make the API design and architecture easier for another developer to understand, add tests for invalid input and failed requests, and improve how the application handles repeated requests and API failures. I would also test the system more thoroughly before submission to ensure that all required features and documentation are present.

Next, I want to deepen my knowledge of backend development, relational databases, API security, and cybersecurity. I also want to learn more about automated testing, deployment, and monitoring applications under realistic workloads. My goal is to use these skills to build secure, scalable applications that solve real-world problems and to continue improving through practical projects and constructive feedback.
